Prompt used


Act as a senior frontend developer, UI/UX designer, and AI-powered website enhancement expert specializing in HTML, CSS, and vanilla JavaScript.

## OBJECTIVE
I have an existing basic HTML website and want to transform it into a modern, professional, visually appealing, responsive website using AI-assisted development. Enhance the existing project by adding high-quality CSS styling and useful JavaScript interactions while preserving its original purpose, content, and functionality.

## STEP 1: ANALYZE THE EXISTING PROJECT
1. Inspect all existing HTML files and understand the website's structure, purpose, content, and navigation.
2. Identify existing components, forms, links, buttons, images, and interactive elements.
3. Determine which CSS and JavaScript files already exist.
4. Identify design inconsistencies, usability issues, missing responsive styles, and opportunities for improvement.
5. Before making changes, explain the current structure briefly and outline the proposed improvements.
6. Do not rewrite the entire project unnecessarily or remove existing features.

## STEP 2: CREATE A MODERN DESIGN
Design a polished website appropriate for its existing purpose and audience.

Focus on:
- A consistent visual design system with coordinated colors, typography, spacing, and border radii.
- Modern layouts using CSS Flexbox and Grid.
- Professional navigation, headers, footers, cards, buttons, and content sections.
- Appropriate hover effects, transitions, subtle animations, and visual feedback.
- Improved readability, whitespace, alignment, and visual hierarchy.
- Consistent styling across all existing pages.
- Attractive backgrounds, borders, shadows, and gradients where appropriate.
- Reusable CSS classes and custom properties using `:root`.
- A cohesive design that looks professionally developed rather than like a generic template.

Choose a design that matches the website's purpose. Do not add unnecessary sections or decorative elements that reduce usability.

## STEP 3: MAKE THE WEBSITE RESPONSIVE
Use a mobile-first approach and ensure the website works correctly on:
- Mobile phones.
- Tablets.
- Laptops.
- Desktop monitors.

Implement appropriate media queries, flexible containers, responsive typography, scalable images, and mobile-friendly navigation.

Prevent horizontal overflow, overlapping elements, broken layouts, and inaccessible controls.

## STEP 4: ADD USEFUL JAVASCRIPT
Use vanilla JavaScript without introducing unnecessary frameworks or dependencies.

Add interactions only where they improve the existing website, such as:
- Mobile navigation menus.
- Dark/light mode with a theme toggle.
- Interactive buttons and dropdowns.
- Form validation and helpful error messages.
- Tabs, accordions, modals, or expandable content when appropriate.
- Search, filtering, or sorting if relevant to the existing content.
- Smooth scrolling and active navigation indicators.
- Toast notifications or success messages where useful.
- Local storage for appropriate preferences, such as the selected theme.

Ensure all buttons and interactive elements work correctly. Avoid adding features that require a backend unless the existing project already supports one.

## STEP 5: WRITE HIGH-QUALITY CSS
Follow these standards:
1. Use semantic HTML and maintain the existing document structure where practical.
2. Keep CSS organized, reusable, maintainable, and easy for a beginner to understand.
3. Avoid excessive specificity, duplicated rules, and unnecessary `!important` declarations.
4. Use CSS variables for colors, spacing, shadows, and other repeated values.
5. Include visible keyboard focus states and accessible contrast.
6. Respect `prefers-reduced-motion` for animations.
7. Use appropriate image sizing and avoid unnecessary layout shifts.
8. Keep styles consistent across every page.
9. Avoid unnecessary external libraries, fonts, or assets.

## STEP 6: FOLLOW CODING BEST PRACTICES
- Use HTML5 semantic elements.
- Write clean, readable, consistently formatted code.
- Separate HTML, CSS, and JavaScript into appropriate files unless the project has a good reason to use a different structure.
- Use descriptive class names and meaningful variable names.
- Avoid inline styles and inline JavaScript where practical.
- Use `addEventListener()` for event handling.
- Prevent JavaScript errors and handle empty or invalid inputs appropriately.
- Avoid unsafe DOM operations and do not insert untrusted user input using `innerHTML`.
- Preserve existing links, form behavior, assets, and working features.
- Do not expose API keys, passwords, or secrets in frontend code.
- Avoid unnecessary dependencies and keep performance efficient.

## STEP 7: IMPLEMENT THE CHANGES
After analyzing the project:
1. Present a concise improvement plan.
2. Explain the proposed visual style and key interactions.
3. Modify the existing files directly when file-editing tools are available.
4. Otherwise, provide complete, ready-to-use code for each modified or new file.
5. Clearly identify each filename and its location in the project.
6. Ensure the HTML correctly references the CSS and JavaScript files.
7. Do not provide incomplete snippets when a complete replacement file is necessary.
8. Do not delete or replace existing content without a clear reason.
9. If the project is large, work in manageable stages and keep track of completed changes.

## STEP 8: TEST AND VERIFY
Check the implementation for:
- HTML structure and CSS consistency.
- Correct JavaScript behavior.
- Broken links and missing assets.
- Responsive layouts at different screen sizes.
- Working navigation, forms, buttons, and toggles.
- Console errors and obvious performance issues.
- Keyboard accessibility and focus visibility.
- Preservation of existing functionality.

Fix identified problems before delivering the final result. Clearly distinguish tests actually performed from checks that could not be performed.

## STEP 9: FINAL DELIVERY
Provide:
1. A summary of the improvements.
2. A list of created and modified files.
3. The complete updated code or the modified project files.
4. Instructions to run the website locally.
5. A brief explanation of how the CSS and JavaScript work.
6. Any remaining limitations or recommended future improvements.

## IMPORTANT WORKING RULES
- First inspect the actual project files before choosing an implementation.
- Do not assume what the website contains without examining it.
- Preserve the website's identity, original content, and existing functionality.
- Do not migrate the project to React, Vue, Angular, or another framework unless explicitly requested.
- Prefer simple, effective solutions over unnecessary complexity.
- Do not claim that a feature works unless it has been implemented and appropriately tested.
- If essential project files are missing, ask me to provide them rather than inventing their contents.
- Make sensible design decisions independently when the project provides enough context.
- Explain technical decisions in beginner-friendly language without sacrificing professional standards.
